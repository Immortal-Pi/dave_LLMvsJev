# Phase 1 — project skeleton, schemas, and offline contracts

Read [the project overview](01-project-overview.md) first. Complete Phase 0 before dependent work in this phase.

### Tasks

Create the package, CLI, configuration validation, logging, mock models, fixture adapter, and a minimal deterministic platformer fixture if necessary. Define the contracts before adding model logic.

Required adapter contract:

```python
class GameAdapter(Protocol):
    def capabilities(self) -> AdapterCapabilities: ...
    def reset(self, scenario_id: str, seed: int) -> Observation: ...
    def observe(self) -> Observation: ...
    def step(self, buttons: frozenset[str], frames: int) -> StepResult: ...
    def save_snapshot(self) -> SnapshotRef: ...
    def load_snapshot(self, snapshot: SnapshotRef) -> Observation: ...
    def close(self) -> None: ...
```

Optional capabilities must be explicitly marked unsupported. Agents never receive an adapter reference or unrestricted memory reads.

Required schemas:

- `Observation`: schema/build version, episode/level ID, simulation frame, monotonic observation ID, player position/velocity/grounded state when available, lives/inventory, observed tiles/entities, local region bounds, score, terminal status, available-field metadata.
- `Entity`: stable ID when possible, actual type, position, measured/derived velocity, last observed frame, visibility, source.
- `Goal`: ID, type, target reference, optional next waypoint, success predicate, constraints, simulation-frame deadline, rationale, source observation ID.
- `SkillCandidate`: candidate ID, skill name, parameters, preconditions, max frames. Each candidate is generated by trusted code.
- `Decision`: chosen candidate ID, source observation/goal ID, optional provider-native score with documented meaning, fallback marker.
- `StepResult`: updated observation, frames advanced, actual applied buttons, events.
- `Event`: type, episode/frame, entity/location references, evidence, certainty, payload.
- `ModelCallRecord`: provider/model, call purpose, timing, retries, status, usage/cost availability, sanitized request/response references.

Use explicit types for pixel positions and tile coordinates. Validate identifiers and ranges. Never execute model-returned Python or arbitrary keyboard commands.

### Acceptance gate

An offline CLI smoke run produces deterministic observations and terminal outcomes without network access. Invalid decisions and unsupported fields are rejected with actionable errors. All tests pass from a clean install.
